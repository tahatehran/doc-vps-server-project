# Contributing to Bore Secure Server Documentation

## 🎯 Welcome Contributors

Thank you for your interest in contributing to the Bore Secure Server Documentation project! This project aims to provide comprehensive, accurate, and user-friendly documentation for the Bore tunneling tool.

## 📋 How to Contribute

### 1. Reporting Issues

#### Common Issues
If you encounter any issues with the documentation, please report them through one of these channels:

- **GitHub Issues**: Create an issue in the [documentation repository](https://github.com/tahatehran/doc-vps-server-project/issues)
- **Discussions**: Post questions or discussions in the [discussions tab](https://github.com/tahatehran/doc-vps-server-project/discussions)

#### Issue Template
When reporting an issue, please include:

```markdown
## Issue Description
[Describe the issue you found]

## Steps to Reproduce
1. [Step 1]
2. [Step 2]
3. [Step 3]

## Expected Behavior
[What should happen]

## Actual Behavior
[What actually happened]

## Environment
- OS: [Your operating system]
- Documentation Version: [Version you're reading]
- Browser: [Your browser version]

## Screenshots
[Attach relevant screenshots if possible]
```

### 2. Improving Documentation

#### Ways You Can Help

**Documentation Improvements**
- Fix typos and grammatical errors
- Improve formatting and organization
- Add missing information or examples
- Update outdated content
- Add diagrams and illustrations

**Code Examples**
- Add new code examples
- Fix broken code snippets
- Improve explanation of existing examples
- Add alternative approaches

**Translation**
- Improve Persian translations
- Add translations to new languages
- Review translation accuracy

**Tools and Scripts**
- Create documentation generation tools
- Add validation scripts
- Create testing utilities

### 3. Creating Pull Requests

#### Branch Strategy
```bash
# Create a feature branch from main
git checkout -b feature/your-feature-name

# Make your changes
# ...

# Commit your changes
git add .
git commit -m "Add your feature description"

# Push to your branch
git push origin feature/your-feature-name

# Create a pull request
# ...
```

#### Pull Request Checklist

- [ ] **Code Examples**: All code examples work and are properly formatted
- [ ] **Documentation**: Content is accurate and follows project style
- [ ] **Translation**: Persian translations are accurate
- [ ] **Links**: All external links are working
- [ ] **Images**: All images are properly referenced and formatted
- [ ] **Tests**: Any validation scripts pass
- [ ] **Security**: No sensitive information is exposed

### 4. Project Standards

#### Code Style
- Use proper indentation (2 spaces for YAML, 4 spaces for Python, etc.)
- Follow existing project formatting
- Keep code examples simple and clear
- Include error handling in examples where appropriate

#### Documentation Style
- Use clear, concise language
- Provide context for all commands
- Include explanation of why commands work
- Add examples for complex concepts
- Use proper Markdown formatting

#### Translation Style
- Maintain accuracy in translation
- Use appropriate terminology
- Consider Persian grammar and syntax
- Review translations for clarity

## 🚀 Pull Request Process

### Step 1: Fork the Repository

1. Go to [https://github.com/tahatehran/doc-vps-server-project](https://github.com/tahatehran/doc-vps-server-project)
2. Click the "Fork" button in the top-right corner
3. Choose your fork repository location

### Step 2: Clone Your Fork

```bash
# Clone your forked repository
git clone https://github.com/your-username/doc-vps-server-project.git

# Navigate to the project directory
cd doc-vps-server-project

# Add the original repository as "upstream"
git remote add upstream https://github.com/tahatehran/doc-vps-server-project.git
```

### Step 3: Set Up Your Branch

```bash
# Create and checkout a new branch
git checkout -b feature/your-feature-name

# Fetch all branches
git fetch upstream

# Merge main from upstream (keeping your changes)
git merge upstream/main
```

### Step 4: Make Your Changes

1. **Edit files** directly using the GitHub interface or locally
2. **Stage your changes**:
```bash
git add .
```

3. **Commit your changes**:
```bash
git commit -m "Add your feature description

- Brief description of changes
- Reference issue number if applicable

Co-authored-by: openhands <openhands@all-hands.dev>"
```

### Step 5: Push and Create Pull Request

```bash
# Push to your remote branch
git push origin feature/your-feature-name

# Go to GitHub and create a pull request
# Compare your branch with main
# Add reviewers and labels
# Write a detailed description
```

### Step 6: Review Process

After creating your pull request:

1. **Automatic Checks**: Wait for automated tests to run
2. **Code Review**: Other contributors will review your changes
3. **Feedback**: Address any feedback or requests for changes
4. **Merge**: Once approved, your changes will be merged

## 🚨 Common Mistakes

### What to Avoid

**Poorly Written Issues**
- Issues without clear reproduction steps
- Issues without expected vs actual behavior
- Issues without environment information
- Issues with vague descriptions

**Incomplete Code Examples**
- Examples that don't work
- Examples without explanation
- Examples with errors
- Examples without context

**Inaccurate Translations**
- Literal translations that don't make sense
- Inconsistent terminology
- Missing context in translation

## 🎯 Getting Started

### First Contributions

If you're new to contributing, try these easy tasks:

1. **Fix Typos**: Look for obvious spelling or grammar errors
2. **Improve Formatting**: Fix indentation, spacing, or structure
3. **Add Examples**: Include an example for a missing concept
4. **Fix Links**: Update broken or outdated links
5. **Improve Translations**: Check and improve Persian translations

### Recommended Order

1. **Week 1**: Fix typos and formatting issues
2. **Week 2**: Add small examples and improvements
3. **Week 3**: Work on translation improvements
4. **Week 4**: Take on larger documentation improvements
